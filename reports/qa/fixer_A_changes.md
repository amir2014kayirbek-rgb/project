## Cross-fixer contracts (my side)
- **K1:** `config.EYE_TAG = os.environ.get("ARALSHIELD_EYE_TAG", "2025v2")`.
- **K2:** `inputs_json.degraded_reasons` contains only codes from {no_weather, no_station_obs, model_missing, clim_fallback, const_fallback, deadline}. `degraded` = 1 iff the list is non-empty. Only no_weather and model_missing switch off M2.
- **K3:** live and backtest `drivers_json` use the same schema; replay `drivers_h1` stays `{feature, contribution}`.
- **K4:** backtest uses `save_forecasts(items, replace_mode="backtest")`.
- **K5:** `inputs_json.issued_at`.
- **K10:** `gates.h{h}.H3_source_features_help`, `H3_delta_pr_auc_ci`, `h1/h2.weather_inputs`, `operational.excluded_stations`, `H4.conclusion_ru/kk`.
- **Fixer B's note:** `dataset.load_sector_source(masked=True)` sets F_s(θ) to NaN in sectors with `coverage < 0.5` (`MIN_SECTOR_COVERAGE`). `features.daily_features` makes `upwind_index`/`source_wind_hours` NaN on days when wind > 8 m/s blew from an uncovered sector (calm days stay 0). `upwind_source_frac` becomes NaN too. The masked map is used by dataset, train (operational check) and predict. `ensure_sector_distance()` returning `{}` (or raising) is tolerated: `source_km` is then None.

## Full dry run on temp copies (truth → dataset → train → backtest → daily)
`ARALSHIELD_DATA` pointed at a scratch copy of the raw ISD/ERA5/CAMS caches, and train `MODELS/REPORTS` were redirected to the scratchpad. Nothing in the project changed. Everything ran without errors.
- **Truth:** 3,328 dust station-days. 37,380 station-days loaded into the temp DB.
- **Dataset:** 113,964 rows, 9,747 events. Kazalinsk years marked ww-unreliable: 2000–2014 and 2016–2022.
- **Train:** 491 s.
  - Test PR-AUC (h0/h1/h2): M2 0.649 / 0.642 / 0.641. Best baseline is now **B2-iso** (0.449), with B2 at 0.389. BSS M2 ≈ 0.39–0.40.
  - B2 rule: gust ≥ 13 m/s and ≥ 1 dry day (dryness adds a little: CSI 0.351 vs 0.340).
  - H3 (paired CI of ΔPR-AUC): h0 [+0.002, +0.020] ✓, **h1 [-0.016, -0.003] ✗**, h2 [+0.001, +0.018] ✓. These numbers predate B's coverage masking (the current `sector_source.json` has no `coverage` yet), so they will change after the regeneration.
  - H4: lags 0 and 1 are significant, lag 2 is not.
  - Replay event is still 2025-04-04. Its drivers are gust_max, wind_max, rh_min, … (no NaN features, no station_code).
- **Operational check:** the first dry run found a bug. `ecmwf_ifs025` returns `snow_depth` as all-null, which gave an object dtype that LightGBM rejects; this would also have broken live `daily`. Fixed with `openmeteo._numeric()`, which casts every variable to float on fetch and on hist-forecast cache read. Re-run results:

  | Model | ERA5 hours identical | Excluded | Period | PR-AUC ERA5 → operational | Wind max ratio vs ERA5 | Gust ratio vs ERA5 | Note |
  |---|---|---|---|---|---|---|---|
  | ecmwf_ifs025 | ≤ 0.016 | none | 2024-02..2025-08 | 0.682 → **0.534** | 0.98 | 0.97 | gusts missing on 50% of days |
  | gfs_seamless | ≤ 0.005 | none | 2022..2025-08 | 0.668 → **0.590** | 1.22 | — | hours > 8 m/s ×2.65; no soil moisture |

- **Backtest:** 20,844 rows.
- **`issue_daily(save=False)`** with the dry models: real Open-Meteo `ecmwf_ifs025`, degraded_reasons `["no_station_obs"]` (NOAA has no 2026 file), M2 used, physical drivers only.

## Not done or partial
- A3 optional lead-time evaluation (`previous_day1/2`) is not implemented, so h1/h2 are only labelled as an upper bound.
- A17/W11: bias is documented only; no quantile mapping.
- A2 trade-off: `ecmwf_ifs025` history has no gusts before 2025-02 and no snow, and `gfs_seamless` has no soil moisture. Both are reported (`by_model`, `missing_share`). The primary result is the first available model.
